## 一、游戏概述

### 1.1 核心体验陈述

在这个游戏里,玩家感受到明亮低多边形世界中短平快的枪战爽感,以及一次次重试后刷新通关评分、逼近"顶点"成绩的成就感。

### 1.2 一句话 Pitch

《顶点射手》是一款全年龄低多边形单机 FPS:3-8 分钟短关卡,像玩街机一样冲高分——用最少的时间、最准的枪法,冲击每一关的顶点评价。

### 1.3 设计支柱

| 支柱 | 含义 | 落地方式 |

| 手感第一 | 枪械手感是所有系统设计的最高优先级,一切为"爽"让步 | 手感参数全部 JSON 化,白盒期即验证,验收标准 = 试玩手感 ≥4/5 |
| 短平快闭环 | 单局 ≤8 分钟,结算与重开 ≤3 秒,重试零成本 | 单关只引入 1 个新元素;结算即见成绩;无死亡惩罚 |

### 1.5 游戏简介

《顶点射手》是一款全年龄向的低多边形单机 FPS。玩家扮演"顶点训练中心"的新晋认证射手,在明亮的训练园区中完成一个个 3-8 分钟的短关卡:清剿训练机器人、限时生存或抵达撤离点。每关结算通关时间、命中率与受击次数,给出 S/A/B/C 评分,驱动玩家反复重试逼近满分。

差异化定位:借竞技 FPS(无畏契约、三角洲行动)级别的枪械手感与武器差异化设计,做单机短关卡冲分玩法——无匹配压力、无挫败惩罚、上手门槛低,面向想"爽快打枪"而非"竞技上分"的泛用户。名字"顶点"即核心承诺:每一关都有一座成绩的顶点,等待玩家征服。

### 1.7 世界观与叙事基调

- **背景设定**:2050 年,"顶点训练中心"(Vertex Training Center)是全球顶尖的轻武器训练与认证机构。玩家扮演新晋学员,在层层递进的训练关卡中冲击射击认证的最高评级——"顶点射手"称号。
- **敌人设定**:训练用自动目标(巡逻机器人、突击机器人、无人机、精英机器人),天然满足全年龄分级——打的是"靶",没有伦理负担。
- **叙事基调**:明快、鼓励式。训练中心 AI 播报员"指导员"在开场播报目标与要点,结算时给出点评(如 S 级:"教科书级的表现,学员。顶点就在眼前。")。
- **叙事原则**:服务玩法,不绑架玩法。无长过场,播报可跳过;叙事载体 = 播报语音 + 结算文案 + 关卡命名。
- **关卡命名主题**:认证等级路线——"1-1 新兵报到 → 1-2 步枪认证 → 1-3 空中目标 → 1-4 近战爆发 → 1-5 顶点认证"。

**播报文案示例(指导员 AI)**

| 场景 | 文案 |
|------|------|
| 1-1 开场 | "学员,欢迎来到顶点训练中心。目标:消灭区域内全部训练目标。枪在手里,靶在眼前。开始。" |
| 1-2 开场 | "步枪认证。领取突击步枪,注意点射节奏。" |
| 1-3 开场 | "空中目标。无人机优先,别让它们开火。" |
| 1-4 开场 | "近战爆发。领好霰弹枪,贴脸才是射程。" |
| 1-5 开场 | "最终认证。全歼目标后,撤离点开启 90 秒。顶点射手的称号,只颁给配得上它的人。" |
| 结算 S | "教科书级的表现,学员。顶点就在眼前。" |
| 结算 A | "漂亮的射击。差一步,就是顶点。" |
| 结算 B | "合格。但顶点训练中心的标准,不止合格。" |
| 结算 C | "重新装弹,再来一次。没有人第一次就满分。" |
| 新纪录 | "新纪录!你已经超越了昨天的自己。" |
| 受击警告 | "注意走位,学员。" |
| 弹药不足 | "弹药见底,记得补充。" |

文案原则:每条 ≤20 字,鼓励式语气、不嘲讽;同一场景准备 2-3 条随机轮换,避免重复疲劳。

## 二、核心玩法设计

### 2.1 核心循环

1. 进入关卡(选关界面显示个人最佳评分)
2. 移动、观察敌人分布与地形
3. 选择武器,消灭敌人 / 完成关卡目标(全歼、限时生存、抵达撤离点)
4. 达成目标,记录通关时间、命中率、受击次数
5. 结算评分(S/A/B/C)与各维度明细
6. 按评分决定:重试冲分,或进入下一关 → 回到 1

循环闭环要点:结算与重开 ≤3 秒,重试零成本——评分是循环的引擎,不是终点。

### 2.2 玩法深度

- 上手门槛:移动 + 射击 + 换弹,5 分钟可上手。
- 策略深度:走位与掩体利用、武器切换时机(近/中/远)、弹药管理、最优路线规划、评分权衡(打得快 vs 打得准)。
- 长期目标:全关卡 S 级评价、刷新个人最佳通关时间、解锁"顶点射手"称号。
- 独立开发适配:深度来自关卡布局与数值调优,而非系统数量堆叠。

### 2.3 主要系统

| 系统 | 如何服务核心体验陈述 |
|------|----------------------|
| 移动与射击手感 | 枪战爽感的载体,一切手感调优的落点 |
| 武器系统 | 提供差异化决策,支撑"何时用哪把枪"的即时思考 |
| 敌人系统 | 战斗压力的来源,决定关卡节奏起伏 |
| 评分系统 | 重复挑战的直接动机,成就感的量化出口 |
| 关卡与目标系统 | 承载以上四系统的舞台,学习曲线的编排者 |

### 2.4 操作方式(PC 键鼠)

| 操作 | 按键 |
|------|------|
| 移动 | WASD |
| 视角 | 鼠标 |
| 射击 | 鼠标左键 |
| 瞄准(ADS,降低扩散) | 鼠标右键 |
| 换弹(可打断) | R |
| 切换武器 | 1 / 2 / 3 |
| 冲刺(短时) | Shift |
| 跳跃 | 空格 |
| 暂停菜单 | Esc |

输入优先级:射击响应 > 移动响应 > 切换/换弹动画,优先保证手感跟手。

**可访问性设置**:鼠标灵敏度(0.2-2.0)、FOV(70-110)、色弱模式(命中标记高对比)、准星颜色/样式切换、播报字幕开关、音量独立调节。

## 三、系统详细设计

### 3.1 移动与射击手感(最高优先级系统)

- **目标**:让"开枪"这件事本身成为爽点;所有参数可调,支撑快速迭代。
- **视角与灵敏度**:FOV 默认 95°(70-110 可调);灵敏度默认 1.0(0.2-2.0,支持 3 位小数)。
- **移动**:行走 5 m/s;冲刺 8 m/s(持续 3s,冷却 5s);空中操控保留 80%。
- **射击手感**:
  - 弹道:即时命中(hitscan),无弹道下坠——保证"指哪打哪"的爽快前提。
  - 步枪后坐力:前 5 发垂直抬升 0.8°/发,随后进入扩散状态(±2°);松开扳机 0.15s 恢复。
  - ADS:扩散 ×0.5,移速 ×0.6,专注精准射击的场景。
  - 换弹:可打断(保留弹匣),换弹音效前置 0.2s,支持"换弹取消"进阶操作。
  - 爆头:1.5× 伤害,命中标记变色(黄色 → 红色)。
- **命中反馈三件套**:准星命中标记 + 伤害数字 + 音效分层(命中/爆头/击杀)。
- **验收标准**:5 名以上试玩者在白盒关卡中手感评分 ≥4/5,未达标不进入下一里程碑。

### 3.2 武器系统

- 目标:提供 2-3 种差异化武器,支撑距离与节奏的即时决策。
- 规则:

| 武器 | 定位 | 伤害 | 射速 | 弹匣 | 换弹 | 射击模式 | 特性 |
|------|------|------|------|------|------|----------|------|
| 手枪 | 初始通用,中距离精准 | 25(爆头 37.5) | 4 发/秒 | 12 | 1.2s | 半自动 | 后坐力小扩散低;持枪移速 ×1.1,弹药最充裕,计分友好 |
| 突击步枪 | 主力,中远距离 | 22(爆头 33) | 10 发/秒 | 30 | 1.8s | 全自动 | 连射扩散渐增适合点射;携带弹药有限,依赖弹药箱 |
| 霰弹枪 | 近战爆发 | 8×10 弹丸(爆头 ×1.5) | 1 发/秒 | 6 | 2.5s | 泵动 | 距离衰减明显,克制冲锋型敌人 |

- 输入输出:数字键切换;敌人掉落弹药与关卡内弹药箱补充;命中反馈 = 伤害数字 + 命中粒子 + 音效。
- 与其他系统:评分系统统计命中率(霰弹枪按弹丸命中折算);敌人类型影响武器选择(霰弹克制突击机器人)。

### 3.3 敌人系统

- 目标:提供由简到繁的战斗压力,让每关有节奏起伏。
- 敌人均为训练机器人/无人机,契合全年龄分级:

| 敌人 | HP | 单发伤害 | 移速 | 感知(距离/视场) | 反应时间 | 攻击间隔 | 行为 |
|------|-----|----------|------|------------------|----------|----------|------|
| 巡逻机器人 | 60 | 8 | 2 m/s | 15m / 60° | 0.5s | 0.8s | 定点巡逻,发现玩家后站立射击 |
| 突击机器人 | 80 | 12(近身) | 4 m/s | 12m / 90° | 0.3s | 1.0s | 发现后直线冲锋,近身碰撞伤害 |
| 无人机 | 40 | 6 | 3 m/s(飘移) | 18m / 360° | 0.4s | 1.2s | 空中横向飘移射击 |
| 精英机器人 | 300 | 10×3(扫射) | 2.5 m/s | 20m / 90° | 0.6s | 3.0s | 阶段性三连扫射,受击可打断 |

- 受击硬直(数值见 data/enemies.json):巡逻 0.15s / 突击 0.2s / 无人机 0.15s / 精英 0.3s(精英扫射受击可打断)。
- AI 结构:有限状态机 = 巡逻 → 警戒(发现玩家)→ 追击 → 攻击;受击反馈 = 闪烁 + 粒子,无血腥表现。
- 与其他系统:关卡目标(全歼/生存)与评分(受击次数)直接关联。

### 3.4 关卡与目标系统

- 关卡目标类型:
  1. **全歼**:消灭区域内全部敌人(基础目标);
  2. **限时生存**:坚持 60-90 秒(时间权重 0.5→0.25,生存权重 0.2→0.45);原型期 5 关暂不启用,预留为后续更新内容(避免稀释"每关只引入 1 个新元素"的学习曲线);
  3. **抵达撤离点**:到达指定出口(时间权重 0.5→0.65,命中权重 0.3→0.25,生存权重 0.2→0.10)。
- 关卡结构:5 关,单关 3-8 分钟;每关只引入 1 个新元素(新武器 / 新敌人 / 混合目标),保证学习曲线平滑。
- 复用策略:模块化场景套件拼装关卡,控制美术成本。
- 与评分系统联动:目标类型决定评分公式的权重切换(各目标权重总和恒为 1.0)。

### 3.5 评分系统

- 评分维度与公式(标准目标):

```
时间分 T = clamp(100 − (通关秒数 − 标准时长) × 1.0, 0, 100)   // 每超出标准 1 秒扣 1 分
命中分 A = 命中率 × 100
生存分 H = max(0, 100 − 受击 ×10 − 死亡 ×30)
总分    = T × 0.5 + A × 0.3 + H × 0.2
```

- 等级:S ≥85,A ≥70,B ≥50,C <50。
- 权重与公式经 4.4 数值自洽性验证调整,原型期按试玩数据继续校准。
- 霰弹枪命中率:原型期按"至少 1 弹丸命中即记为命中"计,避免惩罚近战武器;垂直切片试玩后复核。
- 结算呈现:评分逐项加分动画 → 三维度明细 → 与个人最佳对比 → 新纪录标识("NEW RECORD")与播报点评。
- 数据持久化:本地 JSON 保存每关最佳成绩与历史记录(格式见 6.4)。
- 闭环作用:评分是核心循环的最后一步,也是重试冲分的直接动机。

### 3.6 UI 与用户流程

```
主菜单(开始训练 / 选择关卡 / 设置 / 退出)
   → 选关界面(关卡星级、最佳成绩、解锁状态)
      → 加载
         → 游戏内 HUD(准星 / 血条 / 弹药 / 计时 / 目标提示)
            → 结算界面(评分动画 / 三维度明细 / 历史对比 / 新纪录)
               → 重试本关 / 下一关 / 返回选关
```

- 关键体验指标:结算与重开 ≤3 秒;HUD 信息 ≤5 个常驻元素,不遮挡战斗视线。
- 播报系统:开场目标播报、结算点评,全部配字幕且可跳过。
- HUD 布局规范(5 个常驻元素,位置固定):
  - 中心:准星(命中时闪烁变色);
  - 左上:目标进度(如"目标 3/13");
  - 右上:计时器;
  - 左下:弹药(当前弹匣 / 备弹);
  - 下中:血条(受击时闪红),冲刺冷却以小型图标挂在血条旁,不用数字。

### 3.7 成就与称号系统(评分系统的延伸,不计入五大系统)

- 目标:把"重试冲动"延长为"长期收集冲动",为 7.3 假设 2(重试动力)提供第二引擎。
- 称号清单(本地解锁,展示于选关界面):

| 称号 | 解锁条件 | 设计意图 |
|------|----------|----------|
| 顶点射手 | 全部 5 关获得 S 级 | 终极目标,呼应游戏名 |
| 神射手 | 任意关卡命中率 ≥85% | 奖励精准 |
| 快枪手 | 任意关卡提前标准时长 45 秒以上通关 | 奖励速度 |
| 无伤者 | 任意关卡 0 受击通关 | 奖励完美主义 |
| 一整匣的专注 | 用手枪一个弹匣击杀精英机器人 | 呼应 4.4 数值亮点,引导发现机制 |

- 规则:纯本地记录,无联网;不设"折磨型"成就(如死亡 100 次);每关至少有 1 个可在该关达成的成就。
- 与其他系统:读取评分系统三维度数据判定;写入存档(见 6.4 格式);实现成本 = 判定条件 + 存档字段 + 展示 UI。

## 四、数值设计框架

### 4.1 核心数值体系

- 玩家:生命 100;移动速度 5 m/s;冲刺 8 m/s(持续 3s,冷却 5s)。
- 武器数值:见 3.2 武器表。
- 敌人数值:见 3.3 敌人表。
- TTK 目标:巡逻机器人 0.5-0.8s(步枪 3-4 发);精英机器人 2-3s。
- 经济循环:原型期无经济系统;弹药通过弹药箱与敌人掉落补充,弹药压力即战术压力。

**平衡旋钮清单(全部 JSON 化,改数值不重编译)**:
- 全局:玩家生命、移动/冲刺速度、敌人伤害倍率;
- 武器:伤害/射速/弹匣/换弹时间/后坐力曲线/扩散曲线/ADS 系数;
- 敌人:HP/伤害/速度/感知距离/反应时间/攻击间隔/受击硬直;
- 关卡:标准时长、敌人组合、弹药箱数量与位置;
- 评分:三维度权重、等级阈值。

### 4.2 成长曲线

- 无角色数值成长(原型期):成长完全来自玩家技巧,符合"挑战/精通"动机。
- 难度曲线(每关引入一个新元素,难度提升约 15-20%):

| 关卡 | 新元素 | 标准时长 | S 级要点 |
|------|--------|----------|----------|
| 1-1 新兵报到 | 手枪 + 巡逻机器人 | 3:30 | 教学:移动、射击、换弹 |
| 1-2 步枪认证 | 突击步枪 + 突击机器人 | 4:00 | 中距离点射与近战压力 |
| 1-3 空中目标 | 无人机 + 掩体布局 | 4:30 | 瞄准优先级与走位 |
| 1-4 近战爆发 | 霰弹枪 + 混合编队 | 5:00 | 武器切换决策 |
| 1-5 顶点认证 | 精英机器人 + 混合目标 | 6:00 | 综合检验,关底高潮 |

- S 级时间门槛统一规则:各关 = 标准时长 − 30 秒;命中率与受击门槛见 2.5。

### 4.3 核心指标定义

| 指标 | 目标值/观察方式 | 设计含义 |
|------|------------------|----------|
| 原型完成率 | ≥80% 试玩者通关第 1 关 | 上手门槛是否达标 |
| 平均单局时长 | 3-8 分钟 | 单局节奏与碎片化适配 |
| 自发重试率 | ≥50% 试玩者重试同一关 | 评分循环是否驱动重复挑战 |
| 试玩反馈评分 | 射击手感 ≥4/5 | 核心体验是否成立 |
| demo 下载→愿望单转化 | ≥10% | 题材与定位是否有受众 |
| 退款风险 | 保持低位 | 商店页预期管理(买断制) |

### 4.4 数值自洽性验证(评审记录)

**交叉 TTK 表(全弹命中、贴脸前提、不含换弹)**

| 武器 \ 敌人 | 巡逻 60HP | 突击 80HP | 无人机 40HP | 精英 300HP |
|-------------|-----------|-----------|-------------|------------|
| 手枪 | 3 发 / 0.5s | 4 发 / 0.75s | 2 发 / 0.25s | 12 发 / 2.75s(整匣恰好击杀) |
| 突击步枪 | 3 发 / 0.2s | 4 发 / 0.3s | 2 发 / 0.1s | 14 发 / 1.3s |
| 霰弹枪 | 1 发 / 0s(全弹丸) | 1 发 / 0s(全弹丸) | 远程基本无效 | 4 发 / 3.0s(需贴脸) |

**评分公式敏感性模拟(标准时长 210s 关卡,权重 0.5/0.3/0.2,惩罚 1.0/秒)**

| 玩家类型 | 时间 | 命中率 | 受击 | 时间分 | 命中分 | 生存分 | 总分 | 等级 |
|----------|------|--------|------|--------|--------|--------|------|------|
| 完美选手 | 210s | 90% | 0 | 100 | 90 | 100 | 97 | S |
| 快而浪 | 180s | 60% | 3 | 100 | 60 | 70 | 82 | A |
| 慢而准 | 250s | 95% | 0 | 60 | 95 | 100 | 78.5 | A |
| 求稳过关 | 240s | 80% | 5 | 70 | 80 | 50 | 69 | B |

**验证发现与决策**

1. 原公式缺少上界(大幅提前通关时时间分可超 100)→ 已加 clamp(0,100)。
2. 原权重(0.4/0.3/0.3,惩罚 0.5/秒)下"慢而准"稳定碾压"快而浪",与"快节奏冲分"定位冲突 → 调整为 0.5/0.3/0.2、惩罚 1.0/秒;模拟显示 S 级需"又准又快",任何单项偏科最多 A 级。
3. 步枪各项数值全面优于手枪 → 手枪补两个定位:持枪移速 ×1.1、弹药最充裕(见 3.2),成为"计分与机动"之选。
4. 霰弹对巡逻/突击一枪秒杀 → 预期内的近战反制定位,但依赖贴脸全中;试玩期重点观察"霰弹是否过强"。
5. 霰弹按弹丸折算会惩罚其命中率计分 → 原型期按"至少 1 弹丸命中记为命中",垂直切片后复核。
6. 手枪整匣(12 发 ×25)恰好击杀精英 → 保留为设计亮点("一整匣的专注")。

**调参原则**:权重与阈值均为原型期初值;按 7.4 试玩方案采集数据后校准,目标 = 三类玩家分数分布符合设计意图。

## 五、美术需求清单

- 性能预算:单关 ≤5 万三角面,光照烘焙,保障 60fps。

### 5.3 UI 设计

- 风格:扁平几何,与场景主色板一致。

### 5.4 特效与音频

- 特效:枪口火焰、命中粒子、机器人爆炸粒子(无血腥)。
- 音效:约 30 条——枪声 3 系(近/中/远)、脚步、换弹、受击、击杀、UI、播报。
- 音乐:2-3 首——菜单轻快电子、战斗鼓点、结算短乐句。
- 来源:免费素材库起步,音效在垂直切片阶段替换为定制。

## 六、技术架构建议

### 6.1 推荐引擎

Godot 4:免费开源(MIT 协议,无授权费);3D 管线成熟,支持 low-poly 风格;GDScript 迭代快,单机 FPS 原型社区资料与资产丰富;单人开发维护成本低。

### 6.2 核心技术点

- 第一人称控制器:CharacterBody3D + 头部节点,参数化灵敏度/后坐力/FOV。
- 命中判定:RayCast3D 射线检测(hitscan)+ 命中反馈层。
- 敌人 AI:NavigationAgent3D 寻路 + 有限状态机(巡逻/警戒/追击/攻击)。
- 评分数据:本地 JSON 持久化(最佳成绩、历史记录)。
- 性能目标:1080p 稳定 60fps;low-poly 面数控制 + 遮挡剔除。
- 版本控制:Git + 资产目录规范。

### 6.3 项目结构建议

```
res://
├── scenes/        # player / weapons / enemies / levels
├── scripts/       # 控制器、AI 状态机、评分逻辑
├── assets/        # models / textures / audio / ui
├── data/          # weapons.json, enemies.json, levels.json, player.json, save.json
└── project.godot
```

数值全部外置到 `data/`,关卡参数(敌人组合、标准时长)由 `levels.json` 驱动,策划数值迭代不改代码。

| 事件 | 记录字段 | 用途 |
|------|----------|------|
| level_start / level_end | 关卡、用时、命中率、受击、死亡 | 评分分布与难度校准 |

用途:支撑 7.4 试玩数据采集与 4.4 调参;试玩结束后汇总分析。

## 七、MVP 与垂直切片

### 7.1 MVP 范围

| 模块 | 必须包含 | 暂缓/不做 | 验证目的 |
|------|----------|-----------|----------|
| 核心玩法 | 移动 + 射击 + 换弹 + 1 把武器 | ADS、冲刺、多武器 | 射击手感是否达标 |
| 内容 | 1 个白盒关卡 + 1 种敌人 | 其余关卡与敌人 | 核心循环是否成立 |
| 美术 | 白盒 + 占位模型 | low-poly 全套资产 | 玩法优先,美术后置 |
| 技术 | FPS 控制器 + 命中判定 + 简单 AI | 完整评分、UI 打磨 | 技术可行性 |

### 7.2 垂直切片

1 个 10-15 分钟完整体验,包含:
- 完整 low-poly 场景(1 关)、2 把武器(手枪 + 步枪)、3 种敌人;
- 完整评分结算与 UI、开场播报与教学引导;
- 用途:试玩验证 + 商店页素材(截图/预告片)。

### 7.3 核心假设

| 假设 | 验证方式 | 通过标准 |
|------|----------|----------|
| 射击手感(移动+后坐力+命中反馈)能带来爽感 | 5-10 人试玩问卷 | 手感评分 ≥4/5 |
| 计时评分能驱动重复挑战 | 试玩观察自发重试次数 | ≥50% 试玩者重试同一关 ≥2 次 |
| 全年龄 low-poly 单机冲分 FPS 有受众 | demo 发布后数据 | 下载→愿望单转化 ≥10%,退款率低 |

### 7.4 试玩测试方案

- **测试目标**:验证 7.3 三项核心假设(手感、重试动力、题材受众)。
- **招募**:8-10 人——不常玩 FPS 的泛用户 ≥4 人 + 射击玩家 3-4 人 + 独立游戏爱好者 1-2 人。
- **流程(每人 20-30 分钟)**:
  1. 无引导自由试玩 1-1(5 分钟,记录首个卡点)
  2. 自由试玩 1-1~1-3(10 分钟,观察自发重试行为)
  3. 问卷(10 分钟)
  4. 简短访谈(5 分钟)
- **观察与埋点**:通关时间、命中率、受击、死亡位置、自发重试次数、求助/困惑点、中途退出点。
- **问卷(15 题,可直接打印使用)**:
  - 基本信息(2 题):①玩家类型:泛用户 / 射击玩家 / 独立游戏爱好者;②FPS 经历:几乎不玩 / 偶尔玩 / 常玩竞技 FPS。
  - 量表题(9 题,1-5 分,1=非常不同意,5=非常同意):
    1. 开枪的手感让我觉得爽
    2. 移动与射击的配合跟手
    3. 后坐力与扩散的反馈我能理解并利用
    4. 命中反馈(准星标记 + 伤害数字 + 音效)清晰且有爽感
    5. 1-1 到 1-3 的难度循序渐进、合适
    6. 结算评分让我想立刻再来一局
    7. 我想刷新自己的最佳成绩
    8. 训练场 + 机器人的题材我接受
    9. 我愿意继续玩后续关卡
  - 开放题(4 题):①最爽的时刻是?②最不爽的时刻是?③最想改的一处是?④一句话:会推荐给朋友吗,为什么?
  - 计分规则(对应 7.3 通过标准):手感 = 第 1-4 题均分(≥4.0 通过);重试动力 = 第 6-7 题均分(≥4.0,并与观察到的自发重试率 ≥50% 互相印证);题材接受度 = 第 8 题均分(≥3.5,且第 ④ 题负面理由占比 <30%)。
- **通过标准(对应 7.3)**:手感均分 ≥4.0;≥50% 试玩者自发重试同一关 ≥2 次;题材不符预期反馈 <30%。
- **记录模板**(每名试玩者一行):ID / 玩家类型 / 通关关数 / 各关时间-命中-受击 / 重试次数 / 问卷分 / 访谈要点。

## 九、风险评估

### 9.1 技术风险

| 风险 | 原因 | 影响 | 缓解措施 | 预警信号 |
|------|------|------|----------|----------|
| FPS 手感调优失败 | 后坐力/灵敏度/反馈调校经验不足 | 核心体验不成立,试玩劝退 | 白盒期即验证;参数全 JSON 化快速迭代 | 白盒试玩手感 <4/5 |
| 敌人 AI 开发超支 | 状态机行为扩展失控 | 工期延误,挤压内容生产 | 限定 4 种敌人 4 态;不做复杂行为树 | AI 开发时间超 Phase 2 预算 50% |
| 性能不达标 | 面数/光照超预算 | 掉帧破坏射击体验 | 面数预算 + 遮挡剔除,60fps 硬指标 | 测试机帧率 <60fps |

### 9.2 市场风险

| 风险 | 原因 | 影响 | 缓解措施 | 预警信号 |
|------|------|------|----------|----------|
| demo 无人问津 | FPS 品类红海,独立 demo 淹没 | 愿望单转化低,开发动力受挫 | 明确"街机冲分 FPS"标签;垂直切片出商店页素材 | 发布 2 周愿望单 <100 |
| 全年龄定位与受众预期偏差 | 射击玩家期待硬核/写实 | 差评集中于"太简单/太卡通" | 早期试玩验证题材接受度;商店页如实展示 | ≥30% 试玩者反馈题材不符预期 |
| 买断制定价与内容量预期差 | demo 短,玩家预期高 | 退款率上升 | demo 免费 + 低定价 + 内容量明示 | 退款率 >5% |

### 9.3 生产风险

| 风险 | 原因 | 影响 | 缓解措施 | 预警信号 |
|------|------|------|----------|----------|
| 个人产能不足 | 单线程开发,内容需求大 | 里程碑延期 | 资产商店 + 免费素材;砍非核心内容 | Phase 3 内容完成度 <60% |
| 范围膨胀 | 新点子不断加入 | 核心循环稀释,工期失控 | 新内容过"是否服务核心体验陈述"筛 | 单关开发周期超预算 1.5 倍 |
| 开发动力衰减 | 长期单人开发缺乏反馈 | 项目搁置 | 里程碑绑定外部验证节点(试玩/发布) | 连续 2 周零提交 |
